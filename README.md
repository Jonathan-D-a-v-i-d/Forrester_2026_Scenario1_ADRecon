# Cortex AD-Recon Telemetry Demo

Two native-tooling (LOTL) Active Directory reconnaissance generators for validating detections
and running SOC demos against **Cortex XDR / XSIAM**. They fire the *same* read-only discovery
commands two different ways so you can compare how process-lineage-based correlation behaves.

> **LAB / AUTHORIZED USE ONLY.** Both scripts are intentionally loud and will raise
> high-severity alerts. They perform **read-only** discovery (no changes to AD or hosts).
> Run only in an environment you own or are explicitly authorized to test.

## The two telemetry profiles

| | `Invoke-ADReconBurst.ps1` | `Invoke-ADReconScattered.ps1` |
|---|---|---|
| **Process lineage** | one dense tree under a single `powershell.exe` | reparented — no common ancestor |
| **Parent process** | the operator shell | `WmiPrvSE.exe` (WMI) or Task Scheduler/`svchost.exe` |
| **Correlation story** | easy — walk the tree back to patient zero | hard — ~60 "orphan" events, lineage severed |
| **Extra ATT&CK** | discovery techniques only | the above **+ T1047** (WMI) or **+ T1053.005** (Schtasks) |
| **Output captured?** | yes, to the log | no — telemetry lives in Cortex (log records lineage facts) |

The teaching point: severing the tree makes lineage correlation harder, but the reparenting
mechanism itself (`WmiPrvSE` spawning `net.exe`, bursts of transient scheduled tasks) is its own
high-fidelity signal. "Scattered" isn't quieter — it's *differently* noisy.

## Running

```powershell
# Preview the full command queue without executing:
.\Invoke-ADReconBurst.ps1 -DryRun
.\Invoke-ADReconScattered.ps1 -DryRun

# Profile 1 - single process tree:
.\Invoke-ADReconBurst.ps1

# Profile 2 - reparented via WMI (default) or the Task Scheduler:
.\Invoke-ADReconScattered.ps1
.\Invoke-ADReconScattered.ps1 -Method Schtasks

# Spread events across the timeline instead of all-at-once:
.\Invoke-ADReconBurst.ps1 -JitterMs 300
```

Each run writes a timestamped transcript (`ADReconBurst_*.log` / `ADReconScattered_*.log`) with
one line per action, tagged `[Category|T####]`.

## What runs

Native Windows + RSAT tooling only; nothing is downloaded. RSAT-dependent items
(`dsquery`, `setspn`, `repadmin`, `dcdiag`, `netdom`, the `ActiveDirectory` module) are logged
as **SKIP** if not installed, and the burst continues.

| Phase | Tools |
|---|---|
| Identity | `whoami /all /groups /priv`, `klist` |
| Host / network | `systeminfo`, `ipconfig /all`, `arp`, `route`, `netstat -ano`, `tasklist /v`, `qwinsta`, `quser` |
| Domain / DC / trusts | `nltest /dclist /domain_trusts /trusted_domains /dsgetdc` |
| Account / group enum | `net user/group/accounts/localgroup` (Domain/Enterprise/Schema Admins, Operators, RDP Users), `net view/share/session/config/time` |
| WMI | `wmic computersystem/ntdomain/useraccount/group` |
| LDAP (RSAT) | `dsquery user/computer/group/subnet`, `setspn -q` |
| DC / replication (RSAT) | `repadmin /showrepl /replsummary`, `dcdiag`, `netdom query dc/fsmo/trust/workstation` |
| DNS / time | `nslookup -type=SRV _ldap._tcp.dc._msdcs.<domain>`, `w32tm /query` |
| Policy | `gpresult /z` |
| AD module (RSAT) | `Get-ADDomain/Forest/Trust/DomainController/DefaultDomainPasswordPolicy/ReplicationSite/ReplicationSubnet/User/Computer/Group/GroupMember/OrganizationalUnit/ServiceAccount/Object` |

## Validation checklist

After each run, confirm in Cortex that you see:

- [ ] A process-execution event per command (cmdline captured), tagged to the right technique.
- [ ] **Burst:** a single process tree rooted at `powershell.exe`; causality chain intact.
- [ ] **Scattered (WMI):** discovery processes parented to `WmiPrvSE.exe`; a `T1047` signal.
- [ ] **Scattered (Schtasks):** a flurry of short-lived scheduled tasks; a `T1053.005` signal.
- [ ] `net.exe` runs show the `net1.exe` child spawn.
- [ ] `nltest` / `net group /domain` / `dsquery` raise domain-recon analytics/BIOCs.
- [ ] Any correlation/causality rule groups the Burst events but struggles with the Scattered run.
